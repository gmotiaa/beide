# model-proxy — контракт edge-функции

Единственный маршрут приложения к моделям:
`https://<project>.supabase.co/functions/v1/model-proxy/v1/chat/completions`
(`MODEL_PROXY_BASE_URL` в `electron/services/agent.ts`). Исходник функции
живёт в hosted-проекте Supabase и **не находится в этом репозитории** — этот
документ фиксирует контракт, который функция обязана выполнять, чтобы
клиентские предохранители имели серверную опору.

## Зачем прокси

Ключ шлюза (EchoGate) существует только на сервере (`app_config`, service
role). Клиент аутентифицируется своим Supabase JWT — компрометация клиента не
раскрывает ключ. Всё, что клиент может «отвязать» пересборкой (гейты лимитов,
Pro-гейт моделей), обязано дублироваться здесь: **это последний рубеж**.

## Обязательные проверки на КАЖДЫЙ запрос

1. **Auth**: валидный JWT пользователя (не anon). 401 иначе.
2. **Планка модели**: если `body.model` имеет `tier: "pro"` в каталоге
   (`src/lib/models.ts` — источник правды дублируется в функцию при деплое),
   а `profiles.plan != 'pro'` → 403 `{ error: "pro_required" }`.
3. **Предпроверка лимитов**: остаток окон + кредиты (та же формула, что в
   `spend_tokens`: `greatest(0, least(h5_left, week_left)) + credits`).
   Если остаток < МИНИМАЛЬНОГО ЗАПАСА (рекомендация: 1000 токенов) →
   429 `{ error: "limit_exceeded" }`. Это закрывает главный клиентский пробел:
   многошаговый прогон агента шлёт десятки запросов, и только серверная
   проверка на каждом из них останавливает прогон при пересборанном клиенте.
4. **Стриминг**: прозрачный pass-through SSE; в конце потока обязан
   присутствовать `usage` (см. ниже).

## Учёт (кто списывает)

Сейчас списание выполняет **клиент**: renderer вызывает RPC
`spend_tokens(total_tokens)` после каждого завершённого assistant-сообщения
(`beide:usage` из main). Функция НЕ должна списывать сама, пока это так —
иначе двойной учёт.

Целевое состояние (когда дойдут руки): списание переносится В функцию
(usage из ответа шлюза → `spend_tokens` от service role), клиентский
`spendActual` становится телеметрией. До тех пор: функция только
ПРЕДПРОВЕРЯЕТ, клиент списывает.

## Синхронизация каталога

`tier`-разметка моделей меняется в `src/lib/models.ts`. При каждом изменении
каталога функцию нужно передеплоить с обновлённым списком Pro-моделей —
проверка п.2 не должна отставать от клиента.

## Как проверить вручную

```bash
# без JWT → 401
curl -i https://<project>.supabase.co/functions/v1/model-proxy/v1/chat/completions \
  -H "Content-Type: application/json" -d '{"model":"gpt-5.6-terra","messages":[]}'

# с JWT free-аккаунта и pro-моделью → 403 pro_required
# с JWT аккаунта с исчерпанными окнами и кредитами → 429 limit_exceeded
```
